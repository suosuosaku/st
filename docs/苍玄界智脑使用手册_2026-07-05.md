# 苍玄界智脑使用手册

## 一、智脑负责什么

苍玄界智脑用于在 SillyTavern 对话前自动整理剧情上下文，重点处理：

1. 按当前场景调度世界书条目。
2. 注入近期剧情摘要、人物关系、动态人设、物品记忆等辅助信息。
3. 根据 MVU 当前变量读取当前地点、当前接触角色、修为、灵石等场景信号。
4. 避免整张大世界卡长期打开大量绿灯条目导致 token 溢出。

智脑不是正文生成器，也不是变量结构脚本。变量更新仍由角色卡内 MVU/变量结构规则处理。

## 二、首次启用步骤

1. 导入角色卡与随卡世界书。
2. 打开智脑面板。
3. 进入“苍玄界”或相关设置页。
4. 开启“世界书调度”与“自动注入调度包”。
5. 点击“应用轻量启用计划”。
6. 确认世界书里基础规则、变量规则、结构分段类条目保持常驻，其他地点/NPC/事件类条目交给智脑按场景注入。

启用后，正常聊天即可。不要手动把所有 NPC 和地点条目都长期开绿灯。

## 三、世界书调度逻辑

智脑当前按以下优先级决定本轮注入：

1. 当前地点。
2. 当前地点包含的本地 NPC、宗门、二级地点、规则条目。
3. 当前接触角色。
4. 玩家本轮输入直接提到的角色、地点、行为。
5. 与行为相关的规则，如战斗、交易、移动、秘境、道友互动。

基础规则类条目默认作为底座保持启用，不重复塞进智脑调度包。这样可以减少重复 token，同时防止 MVU 秘闻、八卦、摘要文本误触发大量原世界书条目。

## 四、当前地点包示例

当 MVU 当前地点为“冰原雪域”时，智脑会倾向注入：

1. 冰原雪域。
2. 玄霜宫、风雪堂、寒渊冰市、白夜裂谷等本地地点。
3. 凌长霜、白炉生、宋听雪、雪照宁等本地可能出现人物。
4. 玩家输入直接命中的额外人物或规则。

例如玩家输入“有个试药的没收住，喷出火给丹炉炸了”，会额外命中“贰叁捌”，但不会因为摘要里出现无关人物名就乱拉其他地区人物。

## 五、推荐测试流程

1. 新建测试聊天。
2. 开启智脑和世界书调度。
3. 点击“应用轻量启用计划”。
4. 选择一个专属开场白，例如凌长霜相关开场。
5. 发送一句场景内输入。
6. 查看智脑面板里的最近调度条目。
7. 核对调度结果是否包含当前地点、在场人物、本地可能出现 NPC 和相关规则。

期望结果：

1. 不出现 `string`、变量类型片段、模板代码片段。
2. 不因为摘要、秘闻、八卦里提到某人就注入无关人物。
3. 当前地点为冰原雪域时，应能看到冰原雪域本地条目与本地人物。
4. 当前地点改变后，调度条目随地点切换。

## 六、常见问题

### 1. 为什么点了智脑后世界书绿灯少了

这是正常结果。轻量启用计划会让底座规则常驻，把地点、NPC、事件交给智脑按场景临时注入。

### 2. 为什么只靠输入角色名也能触发人物

玩家本轮输入直接点名属于强证据。当前接触人物也属于强证据。

### 3. 为什么摘要里出现角色名不应该触发人物

摘要和秘闻可能包含大量远方信息，直接用它们触发世界书会造成污染。当前版本调度只把用户输入和 MVU 当前场景快照作为核心证据。

### 4. 如果某个地点缺少本地 NPC 怎么办

需要把该 NPC 放入对应地点包，或让该 NPC 世界书条目里明确写入常驻地点、宗门、区域关键词。

### 5. 什么时候需要重新应用轻量启用计划

导入新版世界书、手动大幅修改世界书绿灯状态、发现大量无关条目常驻时，重新应用一次即可。

## 七、维护注意事项

1. 不要把管理员密钥、Cloudflare Secret、GitHub Token 写进角色卡。
2. 不要把全部 NPC 条目长期设为绿灯。
3. 新增地点或势力时，应同步补充地点包和本地 NPC 关系。
4. 新增人物时，世界书条目名、绿灯关键词、状态栏名称应保持一致。
5. 测试时优先看“最近调度条目”和实际注入内容，不只看世界书绿灯数量。
