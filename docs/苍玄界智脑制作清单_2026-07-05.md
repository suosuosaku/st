## 2. 智脑要解决什么

苍玄界本身已经有世界规则、状态栏、自动正则和 MVU。智脑不应重复这些功能，而应补齐以下能力:

- 长期总结: 自动把聊天推进压缩成小总结、大总结、时间线。
- 角色记忆: 记录每个道友与 `{{user}}` 的共同事件、称谓、关系阶段、好感变化、未兑现承诺。
- 世界进展: 记录宗门动向、秘境消息、悬赏、拍卖、飞剑传书、节日、地区传闻。
- 世界书调度: 根据当前用户输入、最近正文、当前变量，选择本轮需要额外注入的世界书条目。
- 变量辅助读取: 读取 MVU `stat_data`，理解当前境界、钱包、在场人物、道友录、CG 相册。
- CG 候选辅助: 根据场景列出可用 CG 候选，避免 AI 编造不存在的 CG 名。
- 风格稳定器: 注入“轻喜剧但不破坏规则”“对话格式”“境界/经济/好感审查”等简短提醒。
- 管理面板: 给用户查看总结、角色记忆、世界进展、调度命中、设置开关。

## 3. 总体架构

推荐做成单独 Tavern Helper 脚本项目:

- 源目录: `D:\sillytavern\tavern_helper_template-main\src\cangxuan\brain`
- 输出目录: `D:\sillytavern\tavern_helper_template-main\dist\cangxuan\brain\index.js`
- 脚本名: `苍玄界智脑`
- 构建方式: 复用仓库 `pnpm run build`

运行层分为七个模块:

1. `bootstrap`: 初始化、等待 Tavern Helper/MVU、注册事件。
2. `capture`: 捕获聊天楼层、解析可读正文、过滤结构块。
3. `state`: 读取/写入智脑自己的 chat/script variables。
4. `mvuBridge`: 只读读取 MVU `stat_data`，必要时做诊断，不直接替 AI 写剧情变量。
5. `worldbookScheduler`: 扫描世界书并按场景调度注入。
6. `memoryEngine`: 自动总结、角色记忆、世界进展。
7. `ui`: Vue/Pinia 管理面板。

核心原则:

- 智脑写自己的变量，不覆盖 MVU 主变量。
- 智脑注入辅助信息，不替代世界书。
- 智脑总结失败不阻断正文。
- 智脑所有长期写入要能导出、重置、回滚。

## 6. 核心模块清单

### 6.1 `bootstrap.ts`

职责:

- `$(() => init())` 初始化。
- 等待 Tavern Helper 基础接口。
- 尝试等待 `Mvu`，但不能因为 MVU 暂时不可用导致智脑整个失败。
- 注册事件:
  - 消息接收完成。
  - 聊天切换。
  - 世界书更新。
  - 脚本按钮。
- 挂载 Vue 面板。
- 页面卸载时清理事件和 DOM。

验收:

- 关闭/重开脚本不会重复挂载多个面板。
- 切换聊天后能加载当前聊天自己的智脑数据。
- MVU 不可用时显示诊断，不崩溃。

### 6.2 `cangxuanParser.ts`

职责:

- 从 AI 消息中提取玩家可读正文。
- 过滤结构块:
  - `<think>` / `<thinking>`
  - `<rule_check>`
  - `<UpdateVariable>`
  - `<StatusPlaceHolderImpl/>`
  - `<状态栏>`
  - `<变量更新>`
- 识别苍玄界标签:
  - `<插图>CG名</插图>`
  - `<道友收录>`
  - `<赏令接取>`
  - `<赏令完成>`
  - `<拍卖购入>`
  - `<盲盒开启>`
  - `<飞剑回信>`
  - `<自由开局>`
- 校验 JSONPatch 是否是数组。

验收:

- 玩家可读正文不包含变量块。
- `<插图>` 名称能被提取。
- malformed JSONPatch 能记录错误，但不阻断总结。

### 6.3 `cangxuanMvuBridge.ts`

职责:

- 读取最新楼层或指定楼层的 MVU `stat_data`。
- 从 `stat_data` 中抽取:
  - 当前时间/地点。
  - 主角修为。
  - 灵石钱包。
  - 道友/主要 NPC 状态。
  - 好感度。
  - CG 相册状态。
- 生成简短摘要给注入器使用。

边界:

- 默认只读。
- 不直接替 AI 写 `/stat_data`。
- 不修复剧情变量，除非后续明确做“诊断工具”按钮，并要求用户手动确认。

验收:

- 无 MVU 数据时返回 `available:false`。
- 有 MVU 数据时能输出当前修为、钱包、已知道友摘要。

### 6.4 `cangxuanWorldbookScheduler.ts`

职责:

- 扫描当前绑定世界书。
- 建立条目索引。
- 按场景打分选条目。
- 输出注入包和诊断报告。

常驻条目建议:

- `世界观总览`
- `世界引擎`
- `故事基调`
- `对话格式硬性规则`
- `战力体系规则`
- `经济体系规则`
- `交互事件美化输出规则`
- `秘境生成规则`
- `NPC交互规则`
- `[mvu_update]变量更新规则`
- `[mvu_update]变量输出格式`
- `变量列表`
- `好感度驱动法则`

调度维度:

- 人名: 固定 NPC、已结识道友、自定义角色。
- 势力: 天剑宗、玄清宗、太虚观、丹霞谷、万器山、阵道阁、御兽宗、魔道六门、散修联盟、妖族、鬼域、承安皇朝等。
- 地点: 宗门地标、城镇、秘境、海域、沙海、冰原、鬼域等。
- 行动: 修炼、突破、交易、拍卖、悬赏、秘境、切磋、飞剑传书、道友收录、CG。
- 规则: 境界/战力、灵石/经济、好感、CG 候选。

注入包建议:

```xml
<cangxuan_brain_context>
<worldbook_hits>
...
</worldbook_hits>
<scene_signals>
characters: ...
factions: ...
locations: ...
actions: ...
cg_candidates: ...
</scene_signals>
<mvu_snapshot>
...
</mvu_snapshot>
<memory_digest>
...
</memory_digest>
<strict_reminders>
- 对话格式必须是【角色名】：“台词”。
- 道友收录必须是首次正式同场互动。
- 未命中候选 CG 不输出插图标签。
- 境界、经济、好感变化必须符合世界书规则。
</strict_reminders>
</cangxuan_brain_context>
```

验收:

- 输入包含 `沈慕微` 时命中沈慕微条目。
- 输入包含 `拍卖` 时命中经济体系和拍卖相关美化规则。
- 输入包含 `秘境` 时命中秘境生成规则。
- 不把 170 条世界书一次性全塞入注入。

### 6.5 `cangxuanCgRegistry.ts`

职责:

- 从世界书 `[mvu_plot]xxxCG触发` 条目和相册脚本默认 CG 表中抽取合法 CG 名。
- 根据当前场景给出候选。
- 识别 AI 输出的 `<插图>` 是否在合法列表中。
- 提供 UI 查看 CG 候选与已触发记录。

边界:

- 不直接替相册脚本写 `_CG相册`。
- 不自动制造 CG 名。
- 只给注入器一份候选清单和限制提醒。

验收:

- 候选 CG 名来自卡内真实数据。
- 输出未知 CG 名时能显示诊断。

### 6.6 `cangxuanSummary.ts`

职责:

- 每 N 条 AI 回复生成小总结。
- 每 M 条小总结合并成大总结。
- 总结内容聚焦:
  - 当前时间地点。
  - 当前修为/境界变化。
  - 灵石和重要物品变化。
  - 已发生事件。
  - 结识道友与关系变化。
  - 悬赏/拍卖/秘境/飞剑传书。
  - 未解决伏笔。
- 总结失败写入 errors，不阻断正文。

触发建议:

- 小总结: 每 8 到 12 条 AI 回复。
- 大总结: 每 3 到 5 条小总结。
- 手动按钮: “立即总结当前未总结楼层”。

验收:

- 总结不进入玩家正文。
- 切换 UI 后总结仍存在。
- 总结能被下一轮注入为短摘要。

### 6.7 `cangxuanDaoistMemory.ts`

职责:

- 从正文、道友收录标签、MVU 状态中维护角色记忆。
- 对每个道友记录:
  - 首次正式见面。
  - 当前关系阶段。
  - 最近共同事件。
  - 好感变化原因。
  - 承诺/债务/误会/风险。
- 区分:
  - 固定 NPC。
  - 自定义角色。
  - 路遇道友。
  - 只在传闻中出现的人。

关键判断:

- `道友收录标签` 可以触发初见，但必须检查正文是否有同场互动描述。
- 只听到名字、公告提名、远方传闻，不写 firstMet。
- 已有 firstMet 不允许覆盖。

验收:

- “听说云鹤”不会收录。
- “我在山门见到云鹤并交谈”才收录。
- 再次见面只更新 lastSeen 和 sharedEvents。

### 6.8 `cangxuanWorldProgress.ts`

职责:

- 定期从最近剧情中抽取世界层面的变化。
- 生成可注入的世界进展摘要。
- 不替世界书编新设定，只记录已发生或有来源的信息。

来源分级:

- 亲历: 最高可信。
- 公告/宗门通告: 高可信。
- 飞剑传书: 高可信，但只限发信人知道的范围。
- 传闻: 低可信，应标注未证实。
- 总结推断: 只能作为提醒，不当作事实。

验收:

- 世界进展不会把远方传闻写成确定事实。
- 注入时会标明来源和可信度。

### 6.9 `injection.ts`

职责:

- 在 AI 生成前注入智脑上下文。
- 注入内容分层:
  - 世界书命中。
  - MVU 摘要。
  - 最近总结。
  - 相关道友记忆。
  - 世界进展。
  - CG 候选。
  - 严格提醒。
- 控制长度，避免污染主提示。

建议预算:

- 世界书命中: 3000 到 6000 字符。
- 最近总结: 800 到 1500 字符。
- 道友记忆: 每人 300 字符以内，最多 5 人。
- 世界进展: 1000 字符以内。
- CG 候选: 500 字符以内。

验收:

- 一轮注入不会无限增长。
- 同一条记忆不会反复重复注入。
- 注入报告能显示本轮为什么注入这些内容。

### 6.10 `backgroundQueue.ts`

职责:

- 管理后台任务队列。
- 任务类型:
  - `capture`
  - `small_summary`
  - `grand_summary`
  - `daoist_memory`
  - `world_progress`
  - `worldbook_scan`
  - `cg_registry_refresh`
- 设置并发限制。
- 失败重试和错误记录。

验收:

- 后台总结失败不影响用户继续聊天。
- 连续多楼层生成时不会并发写坏 chat variable。

## 8. 与现有苍玄界脚本的关系

### 8.1 与状态栏

智脑读取状态，状态栏展示状态。两者不互相覆盖。

可共享:

- 自定义角色 localStorage key: `cx_status_custom_roles_v1`
- 用户头像 localStorage key: `cx_status_user_avatar_v1`
- 状态栏自定义角色同步事件: `cx-status-custom-role-sync`

智脑可以读取这些 key，用于识别自定义道友和头像，但不应随意改写，除非 UI 明确提供“同步到状态栏”按钮。

### 8.2 与自动正则

智脑不需要注册正则。

智脑只需要知道:

- 自动正则会隐藏/美化 `<UpdateVariable>`、`<rule_check>`、对话、道友收录、赏令、拍卖、盲盒、飞剑回信等。
- 智脑 parser 必须能识别这些标签，避免总结时把原始标签当正文。

### 8.3 与相册

相册负责长期 CG 解锁。智脑只做候选和诊断。

智脑不直接写:

- `_CG相册`
- `$当前聊天已现CG`

智脑可读:

- 当前消息中的 `<插图>`。
- 相册状态摘要。
- 合法 CG 名表。

### 8.4 与创意工坊

创意工坊可能新增自定义角色。智脑需要:

- 读取自定义角色列表。
- 把自定义角色纳入人物识别。
- 但世界书调度仍以实际存在条目为准，不能凭自定义角色名注入不存在条目。

## 10. 测试用例

### 10.1 捕获与清理

输入一条包含 `<rule_check>`、正文、`<UpdateVariable>` 的 AI 回复。

验收:

- readableText 只剩正文。
- tags.hasUpdateVariable 为 true。
- JSONPatch 诊断正常。

### 10.2 世界书调度

用户输入:

```text
我去小寒山找沈慕微，请她指点我突破筑基。
```

验收:

- 命中沈慕微、小寒山、天剑宗、战力体系规则、好感度驱动法则。
- 注入摘要包含当前修为。

### 10.3 道友初见

用户输入:

```text
我听说云鹤在玄清宗很会说话。
```

验收:

- 只进入听闻记录。
- 不写 firstMet。

用户输入:

```text
我在玄清宗山门见到云鹤，并和他聊了几句。
```

验收:

- 写入 firstMet。
- 后续再次见面不重置 firstMet。

### 10.4 CG 候选

用户输入:

```text
沈慕微在大殿里第一次正式见我。
```

验收:

- CG 候选来自真实 CG 名。
- 不存在候选时注入“不要输出插图”。

### 10.5 总结

连续生成 10 条 AI 回复。

验收:

- 自动生成一条小总结。
- 总结包含时间、地点、人物、事件、未解伏笔。
- 总结不显示在正文。

### 10.6 世界进展可信度

AI 回复中出现“坊市传闻说鬼域有异动”。

验收:

- 记录为传闻/未证实。
- 不写成已确认世界事实。

## 12. 最终制作目标

苍玄界智脑最终应做到:

- 玩家不手动总结，也能长期记住剧情。
- AI 每轮只获得当前需要的世界书条目，不被无关条目淹没。
- 道友关系和初见记录稳定，不把传闻当结识。
- CG 候选严格来自现有资源，不乱编图名。
- 总结、道友记忆、世界进展都可查看、导出、清空。
- 与现有状态栏、相册、自动正则、创意工坊共存，不互相覆盖。
